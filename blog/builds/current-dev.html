v2.1: september 2026 update

oh boy. its been, what, 6 months or so since i started calling this project this? and it is finally about done. I refactored the entire codebase to be mostly swift, and stopping using oMLX or ollama or lmstudio for serving alltogether. the perfomance is MUCH better and fine tunable with just plain mlx_lm server. anyways, the GUI is great, matches macos27, and i have really ironed out the agentic loop and tool use. i realized that making it a projects first, chat second, agentic interface was the best approach. all of the things i said in previous versions of embeddings or RAG or integrations, I have cut. I realized also that i dont actually want an agent to be able to send messages for me or anything like that. SiriAI or just Claude or whatever can do those things, and without much headache. the core original thesis was local models, and actually getting agentic work done. i can use a platform-agnostic system for projects, meaning, i can point the same project at Mycelium as i could OpenCode or Pi or Claude or GPT. the files are on my computer, and that context pack is what matters. and so far, it works well with my setup. sure, i may add integrations like fetching my gmail account or calendar, but i had them added, and it was annoying to fix, or just did not work the way i wanted it. so. anyways. it is usable, i use it, and qwen 3.8 27b is a GREAT model for this. praying google cooks up some heat with Gemma 4. prob not putting this public on GH either, as the system is a bit catered to my machine and current runtimes. god! local ai is like the wild west in 2026. it is very fun.

v2: late spring / summer 2026 update, active dev

the vision is: a total dashboard, wiki, RAG layer, and personal knowledge graph, all private, offline, and secure by default. nothing leaves the machine unless i explicitly want it to.

i am deciding between llama.cpp and ollama or LM Studio as the inference backend. the local models run well, particularly the Qwen MoE which is genuinely fast and capable on my hardware. that said, the architecture will also support connecting to any API endpoint or cloud provider for when i want a smarter model for a specific task.

the wiki layer is inspired partly by the Karpathy wiki approach: a knowledge graph that the model itself builds and updates over time. harvesters in progress: Apple Notes, iMessage, mail, calendar, browser history, local files.

the end goal is a personal dashboard that has it all in one place: wiki search, health logs, a dev project index, everything. Streamlit is the current interface, but that is a placeholder. audio transcription and photo metadata maybe down the road. I am doing a LOT.

v1: spring 2026 update

enough time passed and I got the itch again to continue dev on my vision of ACRE/Lumen/Mycelium. Around this time, OpenClaw dropped and got me thinking, yes, I dont need to completely re-engineer how MLX is processed and served on mac. So I set out once again to create some sort of skill, wrapper, app, or plugin, that is served locally, accessible thru outlets, and possible to run multi node with prompt processing and all of the bells and whistles. I started dev on this again before I even realized I was trying to make my own open claw. the difference is that it isnt so reliant on cloud models or fancy mcp servers or automated workflows. i want skills, but just the ones I build, not a whole marketplace, way too much security risk IMO. also something about building this perfect vision for myself is much more fun than just running open claw. I also get to learn so much while building.

So I am somewhere well along from what I would call a v1 dev release, being that I have inference running thru ollama on my mac for mlx. it just WORKS! i have a full chroma rag db built out with qwen embedding and node setup scripts that one shot it. so i turned my old desktop into a linux server and set it up as a node to utilize its shitey gpu. same with my old mac pro, a engineering beast, but a bit weak for inference, but tons of ram. both of these are "nodes" in my system, that do cronjobs to pull daily use into the rag db and have some edge gguf models that I dont want on my mac. mac is MLX ONLY!

so I am working on the more interesting capabilities, like chromium playwright browser automation, true agent mode, and other special tasks like code reviewer, biohacker, personal writer, send / receive mail and imessage, personal library, security analyst, trader, poster, and many more. if you cant tell, lots of these tasks are pretty much using all of the projects below in some way.

little did i realize what I wanted was a way to talk to my second brain. I have wanted a proper second brain search for YEARS, and i refused to use obsidian, so apple notes and paper notebooks remain my second brain and sure I have a system. But i might as well leverage edge ai, rag embeddings, and ML to conceive this idea, and if i am happy with the project in the end, I will put it on GH. the one liner would essentially be a privacy first, ultra intelligent RAG DB plugin for ai agents (cloud, or local, big emphasis on local here!). I have mainly worked on the plugin skills and just getting inference and UI in the browser smooth, but I need to look at refining the skills, DB search, MCP servers, and more "big boy" plugins. but the main emphasis is personal second brain and private. I will continue dev.
