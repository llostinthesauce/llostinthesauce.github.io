takeaways:
• Coder-30B is the speed king (74.6 t/s) — 30B MoE with only 3B active
• Dense 27B is tragically slow (14.8 t/s) — ALL 27B params active every token, no MoE sparsity
• 9B dense is only 44 t/s despite being tiny — Gated DeltaNet architecture trades raw speed for quality
• The LMS 35B variant holds TPS nearly constant across all context sizes (70.3 → 68.1) — excellent KV cache efficiency

critical issues found

Qwen3-Coder-30B — all empty responses (0.85 overall). This model's card states "supports only non-thinking mode" — our <think>\n\n</think>\n\n suppression in the quality eval prompt format causes it to output nothing. This is an eval bug, not a model flaw. Fix: skip think suppression for family=coder or qwen3_moe architectures.

Parse errors plague coding scores. DeepSeek judge consistently fails on responses containing markdown code blocks, Python source, or long structured text. 40–50% of coding prompt scores are parse errors. The raw responses are correct — the judge just can't extract the JSON.



verdict — which model when?

use casepick
best quality, correctness-critical Qwen3.6-35B UD
best speed, interactive coding Qwen3.6-35B LMS
fastest, agentic coding loops Qwen3-Coder-30B UD
lightweight / quick tasks Qwen3.5-9B LMS
solid all-round alternative Gemma-4-26B UD
deep reasoning, don't care about speed Qwen3.6-27B LMS
Head-to-head on the 35B MoE: Unsloth Dynamic wins on quality (+30% overall score), LMS Community wins on speed (+28% faster) and lower memory (+8% headroom). If you're doing deep reasoning work, use UD. If you're iterating code fast, use LMS. They're close enough that the right answer is "use whichever you're in the mood for."
